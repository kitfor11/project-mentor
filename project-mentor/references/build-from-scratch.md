# 从零构建讲解清单（场景 B）

> 当用户需要**从零开始构建并学习一个项目**时，按本清单规划与讲解，而不是一口气把项目做完。
> 目标有二：① 让用户学到「从 0 到 1」的完整流程；② 每一步都能跑起来，不悬空。

## 启动前：确认目标与技术栈

- 确认项目目标、大致功能与范围（先做 MVP，不做大而全）。
- 若用户未指定技术栈，给出推荐并说明理由；优先贴合用户想学的技术栈。
- 读取 `references/user-tech-stack.md`；若为空或与本次无关，用一句话询问想重点学什么。

## 规划：拆解重要点 + 定里程碑

- 把「从 0 到 1」拆成有先后顺序的步骤，每步是用户能感知的一次推进。
- 每步显式标注：是「我来讲、我来做」还是「**交给你**」。
- 先给「重要点清单」让用户确认，再动手。

## 典型步骤模板（按项目增删）

1. **项目骨架/结构** —— 我来做，讲清为什么这么分层
2. **数据模型设计** —— 交给你（有思考含量）
3. **后端接口** —— 交给你
4. **前端页面/交互** —— 我讲、你写
5. **前后端联调跑通** —— 我带你
6. **测试 / 收尾** —— 交给你

原则：**每一步都要能跑起来**，不要一次铺太大。

## 每个重要点的讲解侧重（从零构建特有）

- 第一次出现的概念要讲清「为什么需要它」——这是从零构建最大的教学价值。
- 用「如果不这么做会怎样」做对比，帮用户建立判断。
- 用当前项目的真实代码举例，不用教科书例子。

## 交办原则

- 优先交办「有思考含量」的设计环节：数据模型、接口设计、核心业务逻辑。
- 骨架/样板/环境配置我来搭，用户填关键部分。
- 一次只交办一个小任务，给足骨架和提示。

## 交付物

- 每完成一个里程碑，给一个「能跑」的中间状态 + 一两句学到要点的总结。
- 最终收尾：审阅用户代码 + 输出「学习清单」。
