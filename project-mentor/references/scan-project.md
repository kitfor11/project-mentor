# 已有项目扫描与讲解清单（场景 A）

> 当工作目录已有项目时，按本清单带用户读懂项目，**而不是默默扫完代码**。
> 目标有二：① 让用户看懂项目结构；② 快速定位本次任务涉及的重要点。

## 扫描顺序（按这个顺序读，每读一处讲一处）

### 1. 项目骨架（第一眼）
- 读根目录：README、`package.json` / `go.mod` / `requirements.txt` / `pyproject.toml` / `pom.xml` 等。
- 识别：语言、框架、依赖、脚本命令（build / start / test）。
- 讲解：这是什么项目、用什么技术栈、一条命令如何跑起来。

### 2. 目录结构
- 看源码目录、入口文件、分层目录。
- 讲解：每个目录的职责、分层思路（为什么这么组织）。

### 3. 入口与启动流程
- 读入口文件（`main` / `index` / `app` / `server`），追踪启动链路。
- 讲解：应用怎么启动、请求/数据如何流进来。

### 4. 关键模块
- 定位与本次任务相关的模块，读其核心文件。
- 讲解：该模块的职责、对外接口、依赖关系。

### 5. 数据层（如有）
- 找模型/表定义、ORM、迁移文件、数据库连接。
- 讲解：数据如何存储、模型之间什么关系。

## 每读一处，讲什么（「三问」模板）

对每个重要文件/模块，用三问讲清楚，不要贴大段代码：

1. **它是干什么的**（职责，一句话）
2. **它怎么工作**（关键逻辑/接口，1~2 句）
3. **它和别的模块怎么联系**（数据流/调用关系，一句话）

## 如何「边读边讲」而不是「全讲」

- 只讲与「理解项目 + 本次任务」相关的，其余一笔带过。
- 每次读 1~2 个文件就停下来，问一句「看懂了吗 / 要不要细讲」，再继续。
- 用户说「跳过 / 我懂」就快速过，不纠缠。

## 边读边定位重要点

- 读到命中内置关键字段（`important-points.md`）或用户技术栈（`user-tech-stack.md`）的地方，先记下。
- 扫描完汇总成「重要点清单」展示给用户，标注哪些交办、哪些我来做。

## 交付物

完成扫描后，给用户一份「项目地图」摘要：
- 一句话说清项目是什么 + 技术栈
- 关键模块列表（每个一句职责）
- 本次任务涉及的重要点（交办 / 我来做）
